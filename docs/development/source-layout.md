# 소스와 로컬 자료 관리

<!-- 2026-11-05 hoyeon.han: 사용자와 합의한 프로젝트 보관·개발 규칙을 영구 문서로 기록한다. -->

프로그램 소스·재사용 도구·테스트·유지할 문서는 정식 프로젝트 경로에서 Git으로 관리합니다. 에이전트 설정과 실행 결과는 로컬 `.codex/`에 보존하며 Git과 Docker 빌드 문맥에서 제외합니다. 파일을 Codex가 만들었다는 이유로 실행 코드를 `.codex/`에 두지 않습니다.

## 파일을 둘 위치

| 종류 | 위치 | 관리 기준 |
|---|---|---|
| 앱 진입점 | `Home.py` | Git 관리 |
| 화면 | `pages/` | Git 관리, 한국어 UI |
| 업무·인증 처리 | `Src/` | Git 관리, 실제 Excel·DB는 제외 |
| 실행·배포·복구 도구 | `scripts/`, 프로젝트 루트의 기존 시작·배포 스크립트 | Git 관리 |
| 재사용 검증 도구 | `scripts/verification/` | Git 관리, 결과 자료와 분리 |
| 인증·권한 테스트 | `tests/security/` | Python 소스 Git 관리 |
| 배포·이미지·복구 테스트 | `tests/operations/` | Python 소스 Git 관리 |
| 업무별 회귀 테스트 | `tests/test_*.py` | Python 소스 Git 관리 |
| 운영·복구 문서 | `docs/operations/` | Git 관리 |
| 정산 설계 문서 | `docs/settlement/` | Git 관리 |
| 개발 규칙 문서 | `docs/development/` | Git 관리 |
| 에이전트 설정·실행 산출물·릴리스·보고서·worktree | `.codex/` | 로컬 보존, Git·Docker 전체 제외 |
| 새 검증 결과·화면 | `.codex/outputs/verification/` | 로컬 보존, Git·Docker 제외 |
| 개인 업무자료 보존 기준 | `.codex/user-management/data-baseline.json` | 로컬 입력, `--baseline`으로 경로 지정 |
| 개인 에이전트 지침 | 프로젝트 루트의 `AGENTS.md` | 로컬 지침, Git·Docker 제외 |

`.Codex/`에도 같은 제외 정책을 적용합니다. 대소문자를 구분하지 않는 환경에서는 `.codex/`와 같은 폴더일 수 있으며, 구분하는 환경에서도 두 폴더를 소스 저장소로 사용하지 않습니다. 테스트 아래의 실제 Excel·JSON·XML·이미지 등 입력·결과 자료는 기존 제외 정책을 유지합니다. 사용자·거래처 DB, 발주내역, 환경 파일과 인증키도 기존 비공개·제외 규칙을 유지합니다.

## 기존 자료를 보존하는 방법

재사용 코드와 활성 문서만 정식 경로로 옮기고 참조·테스트를 함께 갱신합니다. 기존 실행 결과 JSON·XML·화면·PDF·검증 보고서·릴리스 압축은 원래 `.codex/` 위치에 둡니다. 로컬 산출물 정리를 이유로 외부 아카이브를 만들거나 기존 자료를 삭제·이동하지 않습니다. 기존 배포·복구용 백업 절차를 이 보관 정리와 혼동하지 않습니다.

비소스가 Git에 이미 추적된 경우에는 실제 파일을 보존하고 추적만 해제합니다. 이 변경을 다른 checkout이나 worktree에 적용할 때 파일이 제거될 수 있으므로, 기존 파일 목록·해시를 확인하고 적용 후 원래 위치와 내용이 유지되는지 확인합니다. 다른 작업의 미커밋 변경과 실행 중인 worktree는 정리 대상에 포함하지 않습니다.

개인 baseline은 소스나 공통 테스트 fixture가 아닙니다. 새 checkout에 자동으로 생긴다고 가정하지 않습니다. 이를 사용하는 5개 검증 도구는 준비된 기존 파일을 읽고, 누락·형식 오류·저장소 밖의 대상 경로·현재 파일의 SHA-256 불일치 시 Docker 접촉 전에 한국어 안내와 종료 코드 2로 중단합니다. 보존 검사를 생략하거나 기준을 현재 상태에 맞추어 자동 갱신하지 않습니다.

활성 문서에서는 로컬 보고서를 원격 Git 링크로 연결하지 않습니다. 보관 위치를 프로젝트 루트 기준의 코드 경로로 표시하고 해당 자료가 로컬 참고 기록임을 설명합니다. 과거 통과 수치·배포 기록을 새 실행 결과나 현재 운영 상태로 고쳐 쓰지 않습니다.

## 변경 작업 순서

1. 구현·수정은 `feature/`로 시작하는 별도 브랜치와 worktree에서 진행합니다. 현재 브랜치·작업 경로와 기존 변경을 먼저 확인합니다.
2. 변경할 파일과 내용을 제안하고 사용자의 승인을 받은 뒤 수정합니다. 같은 대화에서 구체적으로 승인된 범위는 그대로 진행합니다.
3. 다른 작업자의 변경을 보존합니다. 기존 코드는 삭제보다 주석 보존을 우선하고, 변경 위치에 날짜와 작성자 `hoyeon.han`을 남깁니다.
4. 프로그램과 검증은 Python 가상환경에서 실행합니다. 변경에 맞는 테스트와 필요한 점검을 통과한 뒤 승인 범위에서 커밋합니다. 실제 자료·계정·키를 시험 데이터로 바꾸지 않습니다.
5. main 병합과 운영 배포는 구현·커밋과 구분하고 각각 사용자의 명시적 승인을 받습니다. 기능 브랜치에서 main을 받아 검증한 사실을 main 반영이나 운영 배포 완료로 설명하지 않습니다.

별도 worktree가 `.codex/worktrees/`에 있어도 그 안은 해당 브랜치의 독립 Git 작업 공간입니다. root의 로컬 자료 ignore를 이유로 내부 소스까지 비소스로 분류하거나 활성 작업 폴더를 삭제하지 않습니다.

## 실행 안내

운영 검증 도구·개인 baseline·결과 옵션은 [운영 안내](../operations/OPERATIONS.md#재사용-검증-도구), 복구 절차는 [롤백 안내](../operations/ROLLBACK.md), 이카운트 출력 설계는 [정산서 기술 문서](../settlement/ecount-settlement-output-alignment.md)를 참고합니다. 문서의 상대경로 명령은 프로젝트 루트에서 실행합니다. 가상환경 경로가 다른 worktree에서는 해당 작업에 승인된 가상환경 실행 파일을 사용합니다.
